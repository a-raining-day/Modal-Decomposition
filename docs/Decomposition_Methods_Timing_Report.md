# 各分解方法计时与质量对比报告（VMD / LMD / FMD / EFD）

> 目的: 补齐 `tests/comparison/` 下 VMD/LMD/FMD/EFD 计时实验的 docs 报告
> （此前只有原始 JSON/CSV 与脚本内 summary）。

> ```powershell

> python tests\comparison\bench_timing.py --method VMD --out tests\comparison\results\vmd
> python tests\comparison\bench_timing.py --method LMD --out tests\comparison\results\lmd_fixed
> python tests\comparison\bench_timing.py --method FMD --out tests\comparison\results\fmd
> python tests\comparison\bench_timing.py --method EFD --out tests\comparison\results\efd_fixed

> 信号/口径: 同 `docs/EMD_Timing_Memory_Quality_Report.md`（case A/B/C，n≤65536，

> 实现身份与参数见 `tests/comparison/workers.py`。

## 1. VMD（三列: MD-VMD / vmdpy / PySDKit）

**Parity 配置**（三列一致）: `alpha=2000, tau=0, DC=0, uniform init, tol=1e-6,
max_iter=500`；模式数 `K`: case A=3、B=3、C=4。MD-VMD 是 `vmdpy` 引擎的库内
facade，所以 MD-VMD 与 vmdpy 的差异只反映包装开销。

### 计时（中位, ms）

| case | n | MD-VMD | vmdpy | PySDKit | PySDKit / vmdpy |
|---|---:|---:|---:|---:|---:|
| A | 256 | 2.23 | 2.03 | 35.59 | 17.5× |
| A | 1024 | 7.10 | 8.19 | 82.75 | 10.1× |
| A | 4096 | 54.12 | 53.60 | 264.02 | 4.9× |
| A | 16384 | 4241 | 4139 | 5436 | 1.3× |
| A | 65536 | 18247 | 16541 | 28185 | 1.7× |
| B | 256 | 123.2 | 125.4 | 132.4 | 1.1× |
| B | 1024 | 19.14 | 15.43 | 299.32 | 19.4× |
| B | 4096 | 27.01 | 32.82 | 805.76 | 24.6× |
| B | 16384 | 254.2 | 234.9 | 4637 | 19.7× |
| B | 65536 | 1371 | 1363 | 31287 | 23.0× |
| C | 256 | 15.71 | 14.72 | 138.04 | 9.4× |
| C | 1024 | 94.03 | 87.19 | 473.80 | 5.4× |
| C | 4096 | 913.9 | 937.1 | 1415.8 | 1.5× |
| C | 16384 | 5729 | 8487 | 7896 | 0.9× |

### 质量（n=16384）

| case | MD-VMD | vmdpy | PySDKit | 模式捕获（best \|corr\|） |
|---|---|---|---|---|
| A | 同 | 同 | 同 | 三方一致: 37 Hz 0.9993、113 Hz 0.9972 |
| B | 同 | 同 | 同 | 三方一致: amfm 0.9995、89 Hz 0.9998、trend 0.9928 |
| C | 同 | 同 | 同 | —（纯噪声） |

要点:
* **三方模式数值一致**（同一 ADMM 求解器的三个实现），差异只在速度。
* **PySDKit 默认路径慢 5–24×**（B 系列最明显）。原因已定位在其源码:
  `store_history=True`（默认）从不重置收敛累加器，ADMM 因此总是跑满 500 次
  迭代；切到 `store_history=False` 时与 vmdpy 同速（B/4096: 0.008 s vs
  0.248 s），模式数值不变。**可行动项: 使用 PySDKit VMD 时显式关掉
  `store_history`**（或换 vmdpy/MD-VMD）。
* C（噪声）上三方都难以提前收敛，差距收敛到 1.0–1.5×。
* 注意: VMD 的 `recon`（Σmodes − S）本就非零（A 0.50、B 0.35、C 2.26）——
  VMD 是带通分解，不含残差行；该列不是误差指标。

## 2. LMD（四列: LMD-H(scipy) / LMD-midpoint / LMD-H(FHT) / PySDKit）

**配置**: 三个库内变体 `max_pf=5`（与 PySDKit 默认 `K=5` 对齐）；
`LMD-H(*)` 为 `envelope="hilbert"`（分别用 scipy 解析信号 / 编译 C 的 SAO FHT
核）；`LMD-midpoint` 为现行默认（极值中点包络）；PySDKit 为经典 Smith
移动平均 LMD。

### 计时（中位, ms）

| case | n | LMD-H(scipy) | LMD-midpoint | LMD-H(FHT) | PySDKit | H 相对 PySDKit |
|---|---:|---:|---:|---:|---:|---:|
| A | 256 | 3.13 | 33.76 | 2.69 | 34.22 | 12.7× |
| A | 1024 | 2.94 | 39.07 | 3.13 | 56.57 | 19.3× |
| A | 4096 | 4.14 | 71.17 | 4.29 | 170.80 | 41.3× |
| A | 16384 | 25.50 | 465.73 | 31.95 | 1544.82 | 60.6× |
| A | 65536 | 77.87 | 1327.62 | 80.86 | 5857.24 | **75.2×** |
| B | 256 | 4.82 | 103.46 | 8.14 | 63.05 | 13.1× |
| B | 1024 | 11.98 | 106.34 | 8.38 | 400.54 | 33.4× |
| B | 4096 | 13.05 | 183.03 | 14.97 | 2044.10 | 156.6× |
| B | 16384 | 33.83 | 344.82 | 27.07 | 1477.89 | 43.7× |
| B | 65536 | 100.46 | 693.55 | 85.64 | 2173.65 | 21.6× |
| C | 256 | 10.44 | 146.60 | 7.44 | 36.85 | 3.5× |
| C | 1024 | 12.55 | 177.92 | 13.64 | 106.04 | 8.4× |
| C | 4096 | 15.76 | 231.66 | 17.53 | 264.01 | 16.7× |
| C | 16384 | 19.46 | 585.03 | 20.82 | 1208.78 | 62.1× |

### 质量（n=16384）

| case | 实现 | 行数 | recon | IO | 模式捕获（best \|corr\|） |
|---|---|---:|---:|---:|---|
| A | LMD-H(scipy) | 6 | 1.6e-15 | −0.283 | 37 Hz 0.8240、113 Hz 0.8425 |
| A | LMD-midpoint | 6 | 3.3e-12 | **−1.000** | 37 Hz **0.0056**、113 Hz 0.0123 |
| A | LMD-H(FHT) | 6 | 2.1e-15 | −0.283 | 同 scipy（0.8240 / 0.8425） |
| A | PySDKit | 6 | 4.4e-16 | 0.005 | 37 Hz 0.8150、113 Hz 0.7391 |
| B | LMD-H(scipy) | 6 | 4.4e-16 | 0.088 | amfm 0.9986、89 Hz 0.9866、trend 0.6809 |
| B | LMD-midpoint | 6 | 4.4e-16 | 0.231 | amfm 0.9937、89 Hz 0.9413、trend **0.9024** |
| B | LMD-H(FHT) | 6 | 4.4e-16 | 0.088 | 同 scipy |
| B | PySDKit | 6 | 4.4e-16 | 0.088 | amfm 0.9884、89 Hz 0.9687、trend 0.9970 |
| C | 三个库内变体 + PySDKit | 6 | ≤6.3e-12 | −1.0（midpoint）/ 0.014（H）/ −0.005（PySDKit） | —（纯噪声） |

要点:
* **Hilbert 包络变体是速度档**: A/65536 上 78–81 ms，比现行默认
  （midpoint, 1328 ms）快 **17×**，比 PySDKit（5857 ms）快 **75×**；
  编译 C 的 FHT 核与 scipy 解析信号在包络上约 1e-14 一致，速度互有胜负
  （B 上 FHT 更快，C 上相同量级）。
* **现状需注意**: `LMD-midpoint`（现行默认）在 case A 双音调上
  **|corr| ≤ 0.012**，且 IO = **−1.000**（PF 之间完全负相关）；同样在 C
  （纯噪声）上 IO = −1.0。相对地，Hilbert 变体与 PySDKit 的结构正常
  （IO −0.28 / +0.005）。B（AM-FM+趋势）上 midpoint 的 trend 捕获最好
  （0.9024 vs H 0.6809）。**这是一个待诊断的行为差异**（本报告只记录事实；
  建议用 A/C 场景复核 midpoint 的 PF 排序与包络语义，或在使用多点/宽带信号
  时优先 `envelope="hilbert"`）。
* **PySDKit LMD 是纯 Python 内循环**（逐样本极值阶梯 + 平滑），随 n 增长最差
  （B/4096 慢 157×）。
* 库内三变体的重构都精确（≤6.3e-12，含中点的分段样条误差）。

## 3. FMD（两列: MD-FMD / PySDKit-FMD）

**⚠️ 配置不等价**（记录现状，不构成实现优劣结论）: 库内使用有界配置
`K=3, max_iter=10, num_hand=3, seed=0`（`K=-1` auto 模式在含噪信号上会挂起，
见 `workers.py` 注释）；PySDKit 使用 `mode_num=3, cut_num=7, filter_size=30,
max_iter_num=20`。

### 计时（中位, ms）

| case | n | MD-FMD | PySDKit-FMD | 比值 |
|---|---:|---:|---:|---:|
| A | 256 | 97.9 | 42.0 | 2.3× |
| A | 1024 | 3016 | 333 | 9.0× |
| A | 4096 | 12776 | 1242 | 10.3× |
| A | 16384 | 53507 | 4219 | 12.7× |
| A | 65536 | 226431 | 26358 | 8.6× |
| B | 1024 | 2441 | 354 | 6.9× |
| B | 4096 | 10477 | 1190 | 8.8× |
| B | 16384 | 43805 | 3931 | 11.1× |
| B | 65536 | 198076 | 27222 | 7.3× |
| C | 1024 | 715 | 369 | 1.9× |
| C | 4096 | 2726 | 1105 | 2.5× |
| C | 16384 | 16878 | 4133 | 4.1× |

### 质量（n=16384）

| case | MD-FMD | PySDKit-FMD |
|---|---|---|
| A | 37 Hz 0.373、113 Hz 0.166，IO −0.886 | 37 Hz 0.691、113 Hz 0.345，IO −0.566 |
| B | amfm 0.816、89 Hz 0.470、trend 0.164，IO −0.187 | amfm 0.862、89 Hz 0.507、trend **0.999**，IO **+0.020** |
| C | —，IO −0.9997 | —，IO −0.943 |

要点:
* 库内 FMD 当前比 PySDKit 移植慢 **1.9–12.7×**，模式捕获也更低——但两者
  参数不同（迭代上限 10 vs 20、滤波器/带宽设置不同），**不能据此判定实现
  优劣**；要得到可比结论需先把两侧参数对齐（并把 `K=-1` 自动模式在噪声上
  的挂起修好）。
* 可行动项: ①对齐 FMD 参数后再基准；②修复 `K=-1` 自动模式在含噪信号上的
  挂起（当前只能使用有界 K）；③C（纯噪声）上两实现的 IO 都趋近 −1，说明
  FMD 对纯噪声的 PF 结构本身不理想。

## 4. EFD（两列: MD-EFD / PySDKit-EFD，参数等价 `max_IMFs=3`）

### 计时（中位, ms）

| case | n | MD-EFD | PySDKit-EFD | 比值 |
|---|---:|---:|---:|---:|
| A | 256 | 0.80 | 0.60 | 1.33× |
| A | 1024 | 1.40 | 0.80 | 1.75× |
| A | 4096 | 3.80 | 2.40 | 1.58× |
| A | 16384 | 14.5 | 8.7 | 1.67× |
| A | 65536 | 61.2 | 59.9 | 1.02× |
| B | 4096 | 4.0 | 2.1 | 1.90× |
| B | 16384 | 13.8 | 8.7 | 1.59× |
| B | 65536 | 55.9 | 56.6 | 0.99× |
| C | 16384 | 14.6 | 8.5 | 1.72× |

### 质量（n=16384）

| case | MD-EFD | PySDKit-EFD |
|---|---|---|
| A | 37 Hz 0.888、113 Hz 0.443，IO −8.2e-9 | 37 Hz **0.998**、113 Hz **0.994**，IO −8.3e-5 |
| B | amfm **0.979**、89 Hz 0.99997、trend 0.201，IO −1.0e-7 | amfm 0.872、89 Hz 0.99987、trend **0.989**，IO −8.3e-4 |
| C | —，IO −1.1e-7 | —，IO −3.1e-4 |

要点:
* 速度: 小 n 上 PySDKit 快 ~1.6–1.9×（其分段 + 镜像理想带通更轻），
  65536 上两者持平（FFT 主导）。
* 质量: **互有胜负** —— case A（双音调）PySDKit 明显更好（0.998/0.994 vs
  0.888/0.443）；case B 的 amfm 分量库内更好（0.979 vs 0.872），而趋势分量
  PySDKit 更好（0.989 vs 0.201）。EFD 的分段策略（argrelmax 谱分割 vs
  MATLAB `Segm_tec`）不同，处理趋势/噪声的方式随之不同。
* 库内 EFD 的正交性更干净（IO 量级 1e-7–1e-9，PySDKit 1e-4–1e-3）。

## 5. 总结

| 方法 | 库内 vs 外部（速度） | 模式质量 | 结论/可行动项 |
|---|---|---|---|
| VMD | 与 vmdpy 同速（包装开销可忽略）；PySDKit 慢 5–24× | 三方数值一致 | 用 PySDKit VMD 时关 `store_history` |
| LMD | H 变体快 PySDKit 13–75×；midpoint 比 H 慢 17× | H 变体与 PySDKit 正常；**midpoint 在 A/C 上 IO→−1、捕获 ≤0.012** | 诊断 midpoint 的 PF 结构；多点/宽带场景优先 Hilbert |
| FMD | 库内慢 1.9–12.7×（**参数不等价**） | 双方都偏低 | 先对齐参数；修 `K=-1` 挂起 |
| EFD | 小 n 慢 1.6–1.9×，大 n 持平 | 互有胜负（A 外部好、B 各有优劣） | 保持；如需双音调精度可参考 PySDKit 的分段法 |

补充说明:
* 本报告所有数字为同进程、3 次重复中位；VMD/LMD 目录内的 `summary.md` 为
  脚本内单次口径，仅作对照（本报告不采用）。
* 方法与参数身份集中在 `tests/comparison/workers.py`；信号定义在同目录
  `signals.py`。
