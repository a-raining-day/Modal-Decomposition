### 1.5 算法定义（以此为准，**已按算法规范修正**）

设当前残差为 `r`、内层 EMD 为 `E(·; num_imf=1)`（只剥第一阶）、`H(·)` 为解析信号、
`I = sin_smaple_num`：

```text
r ← S
每阶：
  c_src  = E(r).IMFs[0]                        # 第一阶初步 IMF
  z      = H(c_src)                            # 解析信号
  amp    = |z|
  freq   = diff(unwrap(angle(z))) / (2π)，末点复制一份补齐到 N
  ext    = find_peaks(c_src, mod="both")       # 规范①：只在**极值点**上取样
  (freq_c, amp_c) = (freq[ext], amp[ext])      # 极值点 < 4 时退回全样本
  若极值点仍 > cluster_max_samples → 再均匀抽稀    # 兜底，见 §4.3
  (f_c, a_c) = ward 层次聚类(freq_c, amp_c; separation_ratio, max_clusters, cluster_weight)
  for i in 0 .. I-1:
      θ_i    = (2π/I)·i                        # 规范②：np.arange(I)·2π/I，不含 2π 重复端点
      wave_i = a_c · cos(2π·f_c·T + θ_i)       # 辅助正弦：频率确定、幅值来自簇
      imf_i  = E(r + wave_i).IMFs[0]
  IMF_n  = Σ_i imf_i / contrib                 # contrib = 实际剥得出一阶的相位数
  写出 IMF_n ；r ← r − IMF_n
  ！停止：显式阶数到点 / 内层剥不出 / 残差单调 / 每方向极值 < 2 / ‖r‖² ≤ res_energy·‖S‖²
```

四条实现口径，必须与上面这段一起读：

1. **辅助的是确定频率的正弦，不是噪声。** `f_c` 来自 `freq` 的**层次聚类中心**（不是随机抽的），
   `a_c` 来自该簇的**平均瞬时幅值**（不是 `noise_amp · std(S)`）。所以 RPSEMD 既没有
   `noise_amp` / `noise_width` 这类噪声参数，`info` 里也没有 `noise_std`（§10.5、§10.6）。
   这也是它和 EEMD / CEEMD / CEEMDAN / ICEEMDAN 的根本分界：那四个靠**随机噪声**做集平均，
   RPSEMD 靠**同一频率、不同相位**的正弦做平均。
2. **`amp` / `freq` 只在"第一阶初步 IMF 的极值点"上取（规范①，§3.3）。** 非极值点处的
   Hilbert 相位没有物理意义（幅值接近 0 时由噪声主导），把它们纳入聚类只会把伪簇拉进来；
   同时极值点数少于 N，`linkage` 的 O(N²) 被压到极值点的量级（§4.3）。
   估计器本身不变，仍是 `diff(unwrap(angle))/2π`（§5）。
3. **相位网格是 `θ_i = (2π/I)·i`（规范②，§3.4）。** 这样 `Σ_i cos(2πf T + θ_i) = 0`
   **精确成立**，辅助正弦在相位平均里能完全抵消、不残留基线。旧写法 `linspace(0, 2π, I)`
   的末相位 `2π` 与首相位 `0` 重复，实际只有 `I−1` 个不同相位，`Σcos ≠ 0`。
4. **本阶 IMF 是"对相位求平均"，除数是实际贡献的相位数 `contrib`**（某个相位剥不出 IMF 时它会
   被跳过）。这一条与 ICEEMDAN 的「集平均固定除以 M」不同，不会因为个别相位失败而低估本阶。

## 2. 为什么是"正弦辅助"而不是"噪声辅助"

RPSEMD 与前面 EMD / EEMD / CEEMD / CEEMDAN / ICEEMDAN 的差别，一句话：**它把那些引擎里
"随机噪声"的位置换成了"确定频率的正弦"**。这一章说明这个替换在实现上意味着什么，
以及为什么不把它当噪声类引擎看。

### 2.1 与被替代的噪声辅助的关系

| 引擎 | 每阶注入什么 | 幅值怎么定 | 集平均取什么 |
|---|---|---|---|
| EEMD | 白噪声 `w_i` | `noise_amp · std(S)` | 对 M 条独立分解平均 |
| CEEMD | 一对互补白噪声 `±w_i` | 同上 | 对 2M 条互补分解平均 |
| CEEMDAN | 白噪声 → 噪声的第 k 阶 IMF | `noise_amp · std(r_{k−1}) / std(E_k(w))` | 对 M 条平均 |
| ICEEMDAN | `E_k(w)` + 局部均值算子 `M(·)` | 同上 | 对 M 条平均 |
| **RPSEMD** | **`a_c · cos(2π f_c T + θ_i)`** | **簇的平均瞬时幅值 `a_c`** | **对 `sin_smaple_num` 个相位平均** |

两条推论，直接影响 §4–§9 的读法：

1. **`sin_smaple_num` 不是"集成次数"，是"相位分辨率"。** 噪声类引擎增大 `M` 是在换随机实现，
   单调降方差的收益很明确；RPSEMD 增大 `sin_smaple_num` 只是把 `2π` 铺得更细（`θ_i = 2πi/I`），
   它换来的是 `Σcos` 抵消得更干净、相位平均更稳。所以质量**不随** `sin_smaple_num` 单调上升——
   §9 的实测是 4 → 0.6639、**8 → 0.7613**、16 → 0.6901，中间最好。
2. **每阶的成本是 `1 + sin_smaple_num` 次 `EMD(num_imf=1)`**（1 次用于取 `c_src` 估频率，
   `sin_smaple_num` 次用于算各相位的 IMF），再加上一次层次聚类。`num_imf=10` 时就是
   **约 90 次单阶 EMD + 10 次聚类**。§4 的耗时拆解就建立在这个结构上。

### 2.2 聚类那一步在做什么（`hierarchical_clustering`）

```text
输入 : x = freq（被聚类的量）, y = amp（陪着的权重）
       ↑ 顺序是硬约定：x 是频率、y 是幅值。传反是历史 bug（§3 #6）
       ↑ 这两条数组**已经只在极值点上取过样**（规范①，§3.3）；极值点太少时才退回全样本
1. standard=True: x_cluster = (x − mean(x)) / std(x)     # 只用 z 分数做聚类，不改 x 本身
2. Z = scipy.linkage(x_cluster.reshape(-1, 1), method="ward")
3. 从 2 簇开始逐个加簇，直到**所有簇对的中心频率比** max/min > separation_ratio（默认 1.2）：
      lo, hi = min(x_i, x_j), max(x_i, x_j)
      ratio  = hi / lo        # |lo| <= 1e-12 时记 +inf，避免除零（§3 #13）
      只要还有一对 ratio <= separation_ratio 就继续加簇
   max_clusters == -1 → 不设上界，最多试到样本数（防死循环）
   max_clusters >= 2  → for n_clusters in range(2, max_clusters)，**上限开区间**，
                        即 max_clusters=4 时最多试到 3 簇
4. 取"最高频簇"：center_freq = mean(x[mask])、center_amp = mean(y[mask])
   cluster_weight > 0 时先按"簇大小 × 平均幅值"过滤掉权重 < cw·总权重 的簇，再取最高频
5. 返回值必须回到**物理量纲**：center_freq = mean(x[mask])，不是 mean(x_cluster[mask])
```

第 5 条是 §3 #9 的修复点。旧写法在 `standard=True` 下把 z 分数当频率返回（实测 `0.9996`，
真值 `0.091`），辅助正弦的频率因此完全跑偏；现在聚类用 z 分数、**返回物理量纲**。

## 3. 本轮修复的 13 处错误

本轮之前这个引擎（当时叫 `RPSEMD_NEW.py`，转正前的名字）是**完全跑不起来的半成品**：
构造就抛 `TypeError`，越过构造还有一串 `ValueError`。以下 13 类是**语句级**修复（§3.1–§3.2），
函数清单未变（模块级无函数，`get_instantaneous_features` / `hierarchical_clustering`
两个静态方法、其余是方法）。**§3.3–§3.5 是另外两处「偏离算法规范」的修正**，与这 13 处无关，
但它们是本轮质量提升的主因。

### 3.1 修掉的 13 处（按严重度）

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | `unknown = set(kwargs) - ...`（`Ellipsis` 占位符） | 白名单恒为空 → 任何 kwargs（含 `dtype` / `emd_*`）构造即 `TypeError: unsupported operand type(s) for -: 'set' and 'ellipsis'` | 补 **16 项白名单**：`dtype` / `safe` + **14 个 `emd_*`** |
| 2 | `if not isinstance(self.dtype,(type,np.dtype)) or self.dtype is not None` 逻辑反了 | **默认 `dtype=None` 直接抛 `TypeError`** —— 一个都不传也过不了构造 | 改为 `dtype is not None` 才校验，且只要求 `np.dtype(dtype).kind == "f"` |
| 3 | `IMF = self.EMD.decompose(S).IMFs` 返回 `(1, N)`，直接喂给 `hilbert` | `hilbert` 只接受一维 → `ValueError: hilbert 只接受一维实信号` | 取第一行后 `.squeeze()` 成一维（返回值形状见 #5） |
| 4 | `sch.linkage(x, method="ward")` 传一维 | scipy 把一维当**压缩距离矩阵** → `ValueError: Length n ... must be a binomial coefficient` | 改 `reshape(-1, 1)`，明确 `(n_samples, 1)` |
| 5 | `row_imf` 仍是 `(1, N)` | `self.imfs[n, :] = row_imf` 与 `S -= row_imf` 形状不符 | 每次 `np.array(imf_p.squeeze(), copy=True)` 起手累加，保证 `row_imf` 是 `(N,)` |
| 6 | **`amp` 与 `freq` 在调用处传反了**（最关键的一个） | `hierarchical_clustering(x, y)` 里 x 是被聚类的**频率**、y 是**幅值**，而 `decompose` 传的是 `(amp, freq)`。后果：`center_freq` 实际是**平均幅值**（≈0.5–0.6，**大于 Nyquist**）被当成频率；`center_amp` 实际是**平均瞬时频率**（≈0.03）被当成正弦幅值，辅助正弦小了约 **20 倍**、几乎不起作用。这也是 `num_imf=-1` 跑出 **k = 239** 的根因 | 调用改成 `hierarchical_clustering(freq_c, amp_c, ...)`，并在调用点写死注释说明顺序 |
| 7 | `n_imf` 双自增 | `num_imf=3` 时 IMF 写到 idx 0 和 2、idx 1 留 `np.empty` 垃圾，**重构误差 2.51e-02**；`num_imf=2` 直接 `IndexError` | 每阶只自增一次，写 `self.imfs[n_imf, :]` 后再 `n_imf += 1` |
| 8 | 停止判据 `find_peaks(...)[0].size <= 2` 数的是**双向极值总数** | 等价于"每方向 ≥ 1 个"就继续，衰减到只剩 2 个极值时还在硬剥 | 改**分方向**判：`sum(is_max) < 2` 或 `sum(~is_max) < 2` 才停 |
| 9 | `standard=True`（默认）把 `x` **就地 z 化**，`center_freq` 返回 z 分数 | 实测返回 `0.9996`（真值 `0.091`）却被当频率用 → 辅助正弦频率完全跑偏 | 聚类用 z 分数、**返回值换回物理量纲**（`mean(x[mask])`），`x` 本身不再被改写 |
| 10 | `self.max_clusters = S.size` 改写实例状态 | 传 `None` 时实例被写成 `256`，第二次调用行为漂移 | 改局部变量 `max_clusters = S.size if self.max_clusters is None else self.max_clusters` |
| 11 | 显式 `num_imf` 提前 `break` 时不切缓冲区 | **返回未初始化的 `np.empty` 行**（退化输入 `k=3` 全是垃圾内存） | 出口补 `self.imfs = self.imfs[:n_imf, :]` |
| 12 | int / 低精度输入缺 float 强制 | `S -= float` 直接 `UFuncTypeError`（int 数组） | `decompose` 开头：非浮点或 `itemsize < 4` 一律 `Check.to_dtype(S, np.float64)` |
| 13 | 其它参数与边界 | `separation_ratio` 拒收 int；`sin_smaple_num` 收 bool；`max_clusters` 校验误写成 `num_imf > 2` 且放行 `0/1/<-1`；簇中心比 `hi/lo` 未防除零；`max_clusters=-1` 的分簇循环无上界；空结果形状不是 `(0, N)` | 逐条补校验与边界：`max_clusters` 只要 `-1 / None / ≥2`；`ratio` 在 `\|lo\| <= 1e-12` 时取 `inf`；`-1` 循环上界取样本数；空结果统一 `np.empty((0, N))` |

### 3.2 三个能直接看出修好了的指纹

1. **`k = 239` → `k = 3`（修好传参时）→ `k = 4`（规范修正后）**。`num_imf=-1`
   （N=512、`res_energy=1e-2`）在传参传反时会把幅值当频率、辅助正弦几乎为零，于是每阶都
   "剥出"一个同量级的残渣、一路剥到 239 行；修好传参后是 **`k = 3`**，再加上 §3.3/§3.4 的
   规范修正后是 **`k = 4`**、重构 **2.22e-16**（§7）。
2. **重构 2.51e-02 → 4.44e-16**。`num_imf=3` 的双自增（#7）让中间那行留垃圾，
   重建恒等式偏离 2.51e-02；修好后所有档位都在 `1e-16` 量级。
3. **`IndexError` → 正常返回**。`num_imf=2` 在双自增下会写越界；现在是 `k=2`、重构 `1e-16`。

### 3.3 规范化修正一：`amp` / `freq` 只在**极值点**上取（规范①）

**规范原文**：「取第一阶初步 IMF，**对其极值点**计算瞬时幅值和瞬时频率」。

**修正前的做法（偏离）**：`amp` / `freq` 在**全部 N 个样本**上算，然后整条数组进聚类；
为了压 `linkage` 的 O(N²)，又加了 `cluster_max_samples=512` 的均匀抽稀兜底。

**为什么必须改**：Hilbert 瞬时频率只在**极值点附近**有物理意义。非极值点（尤其是幅值
接近 0 的过零点附近）的相位差由噪声主导，`diff(unwrap(angle))` 在那里会给出**远高于
Nyquist 的尖峰**；这些点被一起聚类，就把"伪簇"喂给了"取最高频簇"这一步，辅助频率因此
被拉到偏高的位置。极值点取样同时带来第二个好处：**极值点数少于 N**（A/4096 是 **1203** 个，
占 29.4%；C/4096 是 2980 个，占 72.8%），`linkage` 的 O(N²) 被压到极值点的量级，
再叠加 `cluster_max_samples` 兜底（1203 → 401 点），聚类耗时从 **1695 ms 掉到 8 ms**（§4.4）。

**修法**（`RPSEMD.decompose` 内）：

```python
ext_x, _, _ = find_peaks(IMF, mod="both", safe="safe")
if ext_x.size >= 4:
    amp_cluster, freq_cluster = amp[ext_x], freq[ext_x]
else:                                   # 极值点太少 → 退回全样本
    amp_cluster, freq_cluster = amp, freq
if 0 < self.cluster_max_samples < amp_cluster.size:   # 兜底，见 §4.3
    step = int(np.ceil(amp_cluster.size / self.cluster_max_samples))
    freq_cluster, amp_cluster = freq_cluster[::step], amp_cluster[::step]
```

### 3.4 规范化修正二：相位网格改成 `θ_i = (2π/I)·i`（规范②）

**规范原文**：「`θ_{k,i} = (2π/I)·i, i = 0..I−1`」。

**修正前的做法（偏离）**：`phases = np.linspace(0, 2π, I)`。末相位 `2π` 与首相位 `0` 是
**同一个相位**，所以：

- `I = 8` 的"8 个相位"实际只有 **7 个不同值**，第 8 次 `EMD` 与第 1 次**同输入同输出**；
- 更严重的是 `Σ_i cos(2πf T + θ_i) ≠ 0`。按 `linspace(0, 2π, 8)` 取相位时，
  `Σ_i cos(x + θ_i) = cos(x)`（而不是 0），于是**相位平均后仍然残留 1/8 的辅助正弦**，
  辅助信号无法在集合平均里**精确抵消**——这正是规范要求 `θ_i = 2πi/I` 的原因。

**修法**：

```python
phases = np.arange(self.sin_smaple_num) * (2.0 * np.pi / self.sin_smaple_num)
```

这样 `Σ_i cos(2πf T + θ_i) = 0` 精确成立，`sin_smaple_num` 的有效分辨率也恢复成 `I`（不再
是 `I−1`）。

### 3.5 两处修正合起来的效果（A/4096，`num_imf=10`）

两处是**同一次提交**改的，下表是合起来的效果（分不开归因，机制见 §3.3 / §3.4）：

| 指标 | 规范修正前 | 规范修正后 |
|---|---:|---:|
| `k` | 10 | **8** |
| `mode1` / `mode2` | 0.9855 / 0.9461 | **0.9965 / 0.9550** |
| `IO` | −0.0328 | **+0.0236** |
| `leak` | 0.011 | **0.003** |
| 墙钟（基准脚本） | 273.2 ms | **196.4 ms** |
| 聚类点数 | 512（全样本抽稀） | **401**（1203 个极值点再抽稀） |
| 第 1 阶目标频率 | 0.12991 | 0.16422（真值 0.02759） |

质量、残差、速度三项都变好，而且**`k` 从 10 降到 8**：每阶剥得更干净，残差更早达到停止判据。

## 4. 性能：为什么当年那么慢，现在怎么快

### 4.1 规范修正前的拆解计时（历史）

把一次分解按阶段拆开计时（`.scratch/eemd_new/probe_rpsemd_speed.py`）。下表是
**规范修正前**（`amp`/`freq` 用全 N 样本 + 抽稀到 512）的一批：

| N | 总耗时 | EMD 调用（1+sin_num 次/阶） | 聚类（linkage+fcluster） | 其余（hilbert / 正弦构造 / 残差更新） |
|---|---|---|---|---|
| 1024 | 363 ms | 124 ms (34%) | 96 ms (27%) | 142 ms (39%) |
| 4096 | 1836 ms | 134 ms (7%) | **1695 ms (92%)** | 7 ms |

**结论很反直觉：当时的瓶颈不是"EMD 被调用 90 次"，是聚类。** N=1024 时聚类还只占 27%，
到 N=4096 就吃掉 92%——`linkage` 是 **O(N²)**，而它**每阶都调一次**（10 阶 = 10 次）。

### 4.2 `linkage` 单独的耗时

| 点数 | `linkage` 耗时（同一脚本实测） |
|---:|---:|
| 512 | 1.8 ms |
| 1024 | 7.5 ms |
| 2048 | 33.2 ms |
| 4096 | **183.9 ms** |

点数翻倍耗时约翻 4 倍（1.8 → 7.5 → 33 → 184），是干净的 **O(N²)**；同机另一批测量
4096 点是 155 ms。所以 N=4096 上 `10 × 155–184 ms ≈ 1.6–1.8 s` 就是当年那 1695 ms 的主体。

### 4.3 第一轮加速：`cluster_max_samples`（现行默认，已降级为兜底）

**做法**：参数 `cluster_max_samples: int = 512`。聚类前对 `freq` / `amp` **均匀抽稀**，
步长 `step = ceil(n / max_samples)`，即 `freq[::step], amp[::step]`。

为什么可以抽稀：聚类只用来**确定中心频率**（一个标量），频率分布在均匀抽稀前后几乎一致；
`linkage` 的复杂度却从 O(N²) 掉到 O(512²)。

**规范修正前的五组对照**（A/B/C 三例，`num_imf=10`；成本列是 A/4096）：

| 变体 | 综合 Q | q_A | q_C | q_B | A/4096 耗时 |
|---|---:|---:|---:|---:|---:|
| 不抽稀（base） | 0.6741 | 0.9676 | 0.10 | 0.9546 | 1974 ms |
| **抽稀到 512（采用）** | **0.7140** | 0.9658 | 0.20 | 0.9761 | **96 ms** |
| 抽稀 256 | 0.6851 | 0.9799 | 0.10 | 0.9754 | 108 ms |
| 夹到 Nyquist 内（clamp） | 0.7095 | 0.9791 | 0.20 | 0.9494 | 1738 ms |
| clamp + 抽稀 512 | 0.6882 | 0.9865 | 0.10 | 0.9780 | 116 ms |

当时读出的结论：抽稀 512 又快又不掉质量；`clamp` 单用能提 `q_A` 但拖累 `q_B`、且不解决
O(N²)，**未采用**；`clamp+抽稀` 综合 Q 只有 0.6882，**未采用**。

> **规范修正后这个参数的角色变了**：聚类点数先被极值点降到 N 的 29%–73%（§4.4），
> 512 的上限只在**极值点仍超过 512**时生效。以 A/4096 为例，极值点 1203 个 →
> `step = ceil(1203/512) = 3` → 聚类用 401 点。它现在是**兜底**，不再是主加速手段。

### 4.4 规范修正后：聚类点数变成极值点数

`amp` / `freq` 只在第一阶初步 IMF 的极值点上取（§3.3），于是聚类点数从 `N` 变成
**极值点数**（实测，A/C 的 N=4096 与 A 的 N=16384）：

| 用例 | N | 极值点数 | 占 N | 经 512 兜底后的聚类点数 |
|---|---:|---:|---:|---:|
| A/4096 | 4096 | **1203** | 29.4% | 1203 / 3 = **401** |
| A/16384 | 16384 | **4774** | 29.1% | 4774 / 10 = **478** |
| C/4096 | 4096 | **2980** | 72.8% | 2980 / 6 = **497** |

所以 `linkage` 的平方项被压掉 **64–1024 倍**（点数 512² vs 4096² / 16384²），聚类耗时从
**1695 ms 掉到 8 ms**。新的拆解计时（同一脚本、预热后）：

| N | 总耗时 | EMD 调用 | 聚类 | 其余 |
|---|---|---|---|---|
| 1024（进程内首次，含预热） | 233 ms | 85 ms (37%) | 5 ms (2.2%) | 142 ms (61%) |
| 4096 | 61 ms | 48 ms (79%) | 8 ms (13%) | 5 ms (8%) |

**瓶颈回到了它该在的地方：`1 + sin_smaple_num` 次单阶 EMD。** 这也解释了 §8 里为什么新版
只比旧原生慢 1.2–5.8×、而不再是一个数量级。

### 4.5 端到端

| 档位 | 规范修正前 | 现在（基准脚本） | 倍数 |
|---|---:|---:|---:|
| A/4096 | 2067 ms | **196.4 ms** | 10.5× |
| A/16384 | **35121 ms** | **190.7 ms** | **184×** |

两轮改动叠起来才有这个结果：`cluster_max_samples`（§4.3）先把平方项砍到 512²，
极值点取样（§3.3）再把点数从 512 一路降到 401–497，并且**顺带把质量提上去了**（§3.5）——
不是"用精度换速度"。

顺带一个好处：`info["cluster_infos"]` 里存着每阶的 linkage 矩阵，抽稀后它的形状从
`(N−1, 4)` 降到约 `(400, 4)`，`info` 体积小一个量级。

## 5. 瞬时频率估计：能不能优化？

### 5.1 先澄清一件事：`diff(unwrap(angle))/2π` 不是质量差的根因

`get_instantaneous_features` 用的是最朴素的估计器：

```text
amp  = |z|
freq = diff(unwrap(angle(z))) / (2π)      # 末点复制一份补齐
```

数值上它对**噪声敏感**（`unwrap` 的相位跳变会放大成频率尖峰），所以很容易被怀疑成"质量差的原因"。
**但不是。** 历史上真正的根因是 §3 #6 的**参数传反**；修正后即使估计器仍是这个朴素的
diff-unwrap，A/4096 已经到 `mode1 0.9965 / mode2 0.9550`（§8.2）。
换句话说：**"要不要换估计器"这个问题，在把参数顺序、极值点取样、相位网格（§3.3/§3.4）都
摆正之后，收益空间本来就很小。**

### 5.2 规范修正前的五组估计器对照（历史）

目标频率真值 = `113/4096 = 0.02759`。下表是在**规范修正前**的实现在 A/4096 上测的
（`num_imf=10`，全样本聚类 + 抽稀 512）：

| 变体 | 目标频率[0] | mode1 | mode2 | Q_A | 耗时 |
|---|---:|---:|---:|---:|---:|
| base（diff-unwrap） | 0.12851 | 0.9884 | 0.9468 | 0.9676 | 2017 ms |
| clamp 到 [0, 0.5] | 0.38648 | 0.9874 | 0.9708 | 0.9791 | 1779 ms |
| 幅值门（只留 `amp ≥ 1% max`） | 0.12851 | 0.9884 | 0.9468 | 0.9676 | 1631 ms |
| 共轭乘积 `Im(conj(z)dz)/(2π\|z\|²)` | 0.08710 | 0.9767 | 0.9113 | 0.9440 | 1709 ms |
| 共轭 + 幅值门 | 0.10418 | 0.9823 | 0.9276 | 0.9549 | 1892 ms |

### 5.3 当时的结论（仍然成立）：换估计器没有稳定收益

1. **所有变体都没能让目标频率回到 0.02759。** 最接近的是共轭乘积的 0.08710，仍是真值的 3.2 倍。
   这一点说明：**"目标频率偏高一个量级"不是估计器的问题**，而是"取最高频簇的中心"这个定义
   在含噪信号上的固有偏置。要压下去得改选簇口径（§6），不是换估计器。
2. **共轭乘积更接近真值，但质量更差**：mode1 0.9884 → 0.9767、**mode2 0.9468 → 0.9113（掉 3.5 个点）**。
   真实频率不等于好分解——RPSEMD 需要的是"能把本阶剥干净"的频率，不是"最准"的频率。
3. **幅值门对结果没有影响**（三个指标与 base 逐位相同，耗时反而从 2017 掉到 1631 ms）。
   说明低幅值样本对聚类中心没有实质影响，加门只是少算一点。
4. **`clamp` 能提 `Q_A`**（0.9676 → 0.9791），但 §4.3 已实测它**拖累 `q_B`**、
   且 `clamp+抽稀` 的组合综合 Q 只有 0.6882。**不采用**。

**因此保持 `diff(unwrap(angle))/2π` 不变**。

### 5.4 规范修正后能复跑的两条：base vs clamp

修正后再用同一脚本跑 A/4096（`num_imf=10`；现在 base = 极值点取样 + `θ_i=2πi/I`）：

| 变体 | 目标频率[0] | mode1 | mode2 | Q_A | 耗时（预热后） |
|---|---:|---:|---:|---:|---:|
| **base（现行默认）** | 0.16422 | **0.9965** | **0.9550** | **0.9757** | 55 ms |
| clamp 到 [0, 0.5] | 0.36425 | 0.9957 | **0.9038** | 0.9497 | 80 ms |

`base` 这一行的 `0.9965 / 0.9550` 与 `compare.json` 里新 RPSEMD 的 `c37 / c113` **逐位相同**，
说明基准脚本与探针对得上。`clamp` 在修正后**更差**（`mode2` 0.9550 → 0.9038，掉 5.1 个点），
"不采用"的结论比修正前更强。

### 5.5 为什么没把全部变体重跑一遍：探针与新实现不兼容

`probe_rpsemd_if.py` / `probe_rpsemd_speedup.py` 的 `gate` / `sub` 变体会**把特征数组截短**
（只保留幅值门后的样本、或抽稀到 512 点），而修正后的 `decompose` 要用**极值点索引回原数组**
（`amp[ext_x]`）——两者一碰就 `IndexError`：

```text
IndexError: index 4065 is out of bounds for axis 0 with size 4054
```

这不是实现的问题，是**探针的假设过时了**（它假设聚类输入与 N 等长）。要重跑 gate / sub /
conj 变体，得先按"极值点取样"重写探针；本轮没做，因此 §5.2 仍是修正前的历史数据，
§5.4 只报能跑的 base / clamp 两条。**结论不受影响**：估计器保留 diff-unwrap。

### 5.6 结论

**保持 `diff(unwrap(angle))/2π`**。本轮对频率处理做的**唯一**改动是 §3.3 的
"只在极值点上取值"，估计器本身一行没动。

## 6. 加权选簇：用户要求的评估

### 6.1 机制：`cluster_weight`

`cluster_weight: float = 0.0`。权重 = **簇大小 × 平均幅值**；只有
`权重 ≥ cluster_weight × 总权重` 的簇才参与"取最高频簇"。`0` = 不过滤（原行为，逐位相同）。

动机很具体：Hilbert 变换的**边界跳变**会在 Nyquist 附近造出**样本少、幅值尖**的伪簇，
它常常就是"最高频簇"，于是被当成目标频率。加权过滤掉的正是这类可忽略的簇。

### 6.2 纯双音（无噪）N=1024：加权**确实修好了**伪簇问题

`sig.build_case` 之外单独构造 `sin(2π·37t) + 0.5·sin(2π·113t)`（113 Hz → `0.11035` cycles/sample）：

| `cluster_weight` | 第 1 阶目标频率 | 相对 113 Hz 误差 |
|---|---:|---:|
| `0`（不启用） | **0.25684** | **偏 132.7%** |
| `≥ 0.05` | **0.11002** | **偏 0.3%（正是 113 Hz）** |

这是全章最重要的一行证据：**无噪双音上，不启用加权时"最高频簇"是伪簇（0.25684 ≈ 2.3 倍于
113 Hz）；启用后精确落到 0.11002。** 伪簇问题不是猜的，是量出来的。规范修正后它的幅度
比修正前小（原来 0.48735、偏 341.6%），但**仍然存在**——极值点取样压掉了一部分伪簇，
没有压干净。

### 6.3 基准用例上：加权现在**不再拖后腿**

**(a) A/1024 逐档扫描**（`num_imf=6, max_clusters=8, sin_smaple_num=4`，与 §6.2 同一份探针）：

| `cluster_weight` | 目标频率[0] | mode1 | mode2 | IO |
|---|---:|---:|---:|---:|
| 0 / 0.01 / 0.05 / 0.1 | 0.20982 | 0.9777 | 0.8827 | 0.7489 |
| 0.3 / 0.5 | 0.20982 | 0.9669 | 0.8827 | 0.0659 |

`cw ≤ 0.1` 时**四档输出逐位相同**（加权没有过滤掉任何簇），只有 `cw ≥ 0.3` 才改变解
（`mode1` 掉 1.1 个点、`IO` 从 0.7489 掉到 0.0659）——说明阈值取太大才会误伤。

**(b) 三例综合 Q**（A/4096、B/4096、C/4096，`num_imf=10`，`Q = (q_A+q_C+q_B)/3`，
`q_A` 取 A/4096 一例）：

| `cluster_weight` | Q | q_A | q_C | q_B | 备考 |
|---|---:|---:|---:|---:|---|
| `0`（默认） | 0.7610 | 0.9757 | 0.3333 | 0.9740 | 与 §4 的 base 行一致 |
| `≥ 0.01` | **0.7650** | 0.9757 | 0.3333 | **0.9860** | `q_B` 升 12 个千分点，`q_A`/`q_C` 不变 |

- **`q_A` / `q_C` 完全相同**：A 上第 1 阶的目标频率在两种取值下都是 0.16422 一类，
  C 的行级合规率也没被改动 —— 加权**没有**误删真信号。
- **提升全部来自 `q_B`**（0.9740 → 0.9860，AM-FM 捕获更好）。
- 综合只涨 **0.0040（0.5%）**，落在 `q_C` 的粗分辨率（一格 ≈0.033）之内，**不足以当作
  "默认该打开"的证据**。

### 6.4 结论：**参数保留、默认 0、文档标注"已评估，默认不启用"**

三条事实放在一起：双音上加权能修伪簇（§6.2）；`cw ≤ 0.1` 在 A 上完全无副作用（§6.3a）；
三例综合 Q 只微升 0.5%（§6.3b）。按保守原则 **`cluster_weight` 默认保持 `0.0`**；
参数保留，调用方如果明确知道自己的信号有边界伪簇（或 B 类多分量信号），可以显式打开
`0.01–0.1`。**注意**：只有 §3 #6 修好之后加权才真正生效——修好之前 `amp`/`freq` 传反，
加权是在"平均幅值"上分支，实测 `cw=0` 与 `cw=0.05` 的输出**逐位相同**（现在不同了，§7）。

### 8.3 ⚠️ 横比限制：`k` / `leak` / `IO` 都要小心

- **新 / 旧 RPSEMD 不是同一算法**（§8.1），两者的 `k`、`leak` 由各自的停止判据决定，不能读成
  "谁把信号分解得更好"。可比的只有 `mode1` / `mode2`（"某一行像不像某个音调"）。
- **`leak` 不可横比**：B/4096 上 0.270（新）/ 0.415（旧）里装的是**真实的二次趋势**，
  不是噪声；C/4096 上新 RPSEMD 的 0.012 与旧版的 0.017 语义也不同。
- **`IO` 的符号不能当判据**：新版 A 组是 **+0.0236 / +0.0244**（已经接近 0），
  而 EMD 是 −0.1840 / −0.1718、旧版 B/4096 是 −0.7830。负值不代表算错（`IO` 的下界是 −1），
  **只有绝对值可读**。
- **`k` 不可横比**：新版不再固定吃满 `num_imf=10`——A/4096 是 8、A/16384 是 10、B 是 9、C 是 9，
  早停（残差每向极值 < 2）会提前触发；旧版最高只到 5–8 阶。

> **A/16384 上已经基本追平旧原生**（190.7 vs 158.1 ms）。

**质量（如实写，不挑着说）**：

- **对新版最重要的一条：模式捕获明显好于旧原生。** A/4096 `mode1` 0.9965 vs 0.9422（+0.0543）、
  `mode2` 0.9550 vs 0.8167（**+0.1383**）；A/16384 0.9968 / 0.9578 vs 0.9519 / 0.8402。
  弱音调（113 Hz）的差距最大，这正是"极值点聚类中心 + 簇平均幅值"相对"FFT 谱峰 + 单位幅值正弦"的收益。
  **规范修正把 A/4096 的 `mode1` 从 0.9855 又推高到 0.9965、`mode2` 从 0.9461 到 0.9550。**
- **B/4096 上新版的 `IO` 好得多**：**+0.0741** vs 旧版的 **−0.7830**。
  旧版这一格差，是因为它只剥了 4 阶、`leak` 0.415（趋势几乎全留在残差里），而 `IO` 不计残差，
  剩下几行之间高度相关。B 上真正可比的是 `mode1`/`mode2`：新版 0.9499 / 0.9982 对旧版
  0.9995 / 0.9984，**旧版在 AM-FM 分量上更准**（新版把这部分能量更多留在了残差里，
  `leak` 0.270 对 0.415），如实记录。
- **与 ICEEMDAN 相比**：ICEEMDAN 在 A 上的 `mode1` 仍略高（0.9977 / 0.9984 对 0.9965 / 0.9968）、
  `mode2` 明显更高（0.9877 / 0.9884 对 0.9550 / 0.9578）；`leak` A/4096 是 0.005 对
  **新版的 0.003**（新版更小）/ A/16384 是 0.001 对 0.003（ICEEMDAN 更小）。
  速度上新版**快 3.2–11.0×**（A/16384 2105.9 vs 190.7 ms = 11.0×）。
  C/4096 上 ICEEMDAN 的 `IO` 0.0419 与 `leak` 0.001 都好于新版（0.1824 / 0.012）——
  **纯噪声上 RPSEMD 没有优势**，如实记录。
- **与 EMD 相比**：EMD 最快（A/4096 3.8 ms）也最差（`mode1` 0.7179、`IO` −0.1840），
  但它在 C/4096 上的 `valid` 6/9、`IO` −0.0496 比新版好。**RPSEMD 的收益集中在"含噪弱音调"，
  不是"每个指标都更好"。**

### 8.5 为什么 `valid` 仍然偏低（0–3 行）

`valid` 是 `|zc − ext| ≤ 1` 的 IMF 行数。本引擎每阶的 IMF 是**多个相位上的单阶 EMD 的平均**，
平均后的行不再严格满足经典 IMF 的窄带必要条件（与 ICEEMDAN 的 §6.5 同源）。所以：

- 新版的 `valid` 是 **0–3 行**（A/4096 2/8、A/16384 **0/10**、B/4096 2/9、C/4096 3/9），
  低于 EMD（3–6 行）、也低于 ICEEMDAN 的 1–4 行；
- A/16384 的 **0/10** 是长信号 + 相位平均共同作用的结果，不代表分解错——该格 `recon` 是 8.88e-16；
- **这不是"实现对不对"的证据**，只说明"这一行有多像经典 IMF"。判断质量请看 `mode1` / `mode2` / `recon`。

### 8.6 目标用例（近邻频率分离）实测：规范修正后设计意图兑现

RPSEMD 论文里的卖点是"用确定频率的辅助正弦把**靠得很近**的频率分开"。这一节专门测这条，
因为它是判断"效果"最关键的一条。条件是：**两个等幅近邻音调 + 1% 白噪声，N=2048**；
判据是「**某一阶 IMF 与参考音调的 `|corr| > 0.9` 记 ✓**」——
两个音调还同处一阶时，该阶对任一参考音调的 `|corr| ≈ 0.707`，所以**0.6–0.7 就是"没分开"**。
`Δf·N` 是归一化间隔（cycles/sample × 1000），越小越难分。

| 频率对 | Δf·N | RPSEMD(新) | RPSEMD(旧) | EMD | ICEEMDAN |
|---|---:|---|---|---|---|
| 37/40 Hz | 0.0015 | 0.5904/0.6275 ✗ | 0.6714/0.7149 ✗ | 0.6176/0.5657 ✗ | 0.6930/0.6689 ✗ |
| 37/44 Hz | 0.0034 | 0.6639/0.7137 ✗ | 0.6768/0.7198 ✗ | 0.6765/0.5839 ✗ | 0.6967/0.6726 ✗ |
| 37/50 Hz | 0.0063 | 0.6886/0.7147 ✗ | 0.6658/0.7337 ✗ | 0.6741/0.6015 ✗ | 0.6771/0.6900 ✗ |
| **37/74 Hz（一个八度）** | 0.0181 | **0.9941/0.9675 ✓** | 0.9875/0.9632 ✓ | 0.9900/0.9580 ✓ | 0.9801/0.9444 ✓ |

耗时（同一批用例，单次实测，ms）：

| 频率对 | RPSEMD(新) | RPSEMD(旧) | EMD | ICEEMDAN |
|---|---:|---:|---:|---:|
| 37/40 Hz | 295.0 | 19.3 | 2.4 | 423.5 |
| 37/44 Hz | 55.1 | 19.2 | 2.7 | 436.3 |
| 37/50 Hz | 51.2 | 27.2 | 2.5 | 444.1 |
| 37/74 Hz | 51.8 | 14.4 | 3.1 | 439.5 |

> 37/40 Hz 那一行新版的 **295.0 ms 是首次调用**（含一次性预热），同配置的后三行是 51–55 ms；
> 读耗时请看后三行。

**结论（如实写，与修正前的版本相反）**：**规范修正后设计意图兑现：八度级间隔上分辨率最高。**

- **3–13 Hz 的近邻音调四家仍然都分不开**（0.5904–0.7337，全部 < 0.9，即两音仍在同一阶）。
  这已经低于 EMD 的分辨极限，属**物理限制**——`Δf·N ≤ 0.0063` 时两音的拍长超过窗长，
  任何 EMD 家族的筛分都分不开，不是新版退步。
- **到了八度级（37/74，`Δf·N = 0.0181`），四家都能分开，而新版 RPSEMD 的捕获率最高**：
  **0.9941/0.9675**，优于旧版 0.9875/0.9632、EMD 0.9900/0.9580、ICEEMDAN 0.9801/0.9444。
  修正前这一格新版只有 0.911/0.891（分不开），**极值点取样 + 相位网格两处修正把它从
  "不如 EMD" 拉到了"四家最高"**。
- 综合起来，新版现在的定位是：**含噪弱音调捕获优于旧版与 EMD（§8.2/§8.4）、近邻分辨在八度级
  最高（本节）、速度比 ICEEMDAN 快 3.2–11.0×**；仍然打不过 ICEEMDAN 的 `mode2`
  （0.9550 对 0.9877），也**分不开 3–13 Hz 的近邻音调**（那是物理限制）。

### 9.4 前沿与选点

**Pareto 前沿有 2 个点**（`pareto_sweep.json` 的 `front`）：

| # | ratio | sin_num | max_clusters | t_ms | Q | mode2 | leak |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 1.2 | 4 | 4 | **104.5** | 0.6639 | 0.9521 | 0.0015 |
| 1 | 1.2 | 8 | 4 | 189.7 | **0.7613** | 0.9550 | 0.0025 |

前沿只有 2 个点，因为 **Q 只有 3 个取值**（0.6639 / 0.6901 / 0.7613）：`(1.2, 8, 4)` 是最高 Q
且同 Q 组里最省；`(1.2, 4, 4)` 便宜 45%（104.5 vs 189.7 ms）但 Q 低 0.0974，所以也在前沿上。
`sin_num=16` 的 9 组 Q 全被 `(1.2, 8, 4)` 支配（Q 更低、耗时更高）。

**选点规则**（`pick_rule` 原文）：可行域（`leak ≤ 5%`）内 `Q` 达到最优 **99.5%** 的最省点；
`separation_ratio` 与 `max_clusters` 的 Q 逐位相同（前者因 2 簇即刻满足分离、后者因上界从未触到），
故 `ratio` 取论文推荐 **1.5**、`mc` 取最省的 **4**。

| 锚点 | ratio | sin_num | max_clusters | Q | t_ms | leak | mode2 |
|---|---:|---:|---:|---:|---:|---:|---:|
| `best_feasible` | 1.2 | 8 | 4 | 0.7613 | 189.7 | 0.0025 | 0.9550 |
| **`pick`（最终默认）** | **1.5** | **8** | **4** | **0.7613** | **190.5** | **0.0025** | **0.9550** |

- 可行域**非空且极宽**：27 组 `leak` 全部 ≤ **0.0026**，`leak ≤ 0.05` 的约束**没有筛掉任何点**。
  （`leak` 比修正前的 0.0073–0.0253 又小了一个量级。）
- 阈值 `0.7613 × 0.995 = 0.7575`，满足的正是 9 个 `sin_num=8` 的点；
  最省的是 `(1.2, 8, 4)` 的 189.7 ms，按规则把 `ratio` 换成论文值 1.5（`(1.5, 8, 4)`，190.5 ms）。
- **最终默认值**：`max_clusters=4`（原 `None`，即信号长度）、`sin_smaple_num=8`（原 `100`）、
  `separation_ratio=1.5`（保持论文值）、`num_imf=10`（由用户定，不算"调出来的"）。

### 9.5 ⚠️ 读 `Q` 的警告：8 不是"纯质量最优"

必须说明，否则会误以为 `sin_smaple_num=8` 是质量最好的档：

1. **`q_C` 是诊断量、分辨率很粗**。C/4096 的合规行率只取 `0.10 / 0.33` 这些值
   （跳一格折进 `Q` 就是 ±0.07 量级）。`sin_num=8` 之所以赢，是它同时拿到 `q_C=0.3333`
   与很高的 `q_A/q_B`；`sin_num=16` 的 `q_A=0.9749`、`q_B=0.9955` 里 `q_B` 是**全表最高**，
   但 `q_C` 掉到 0.10，把 Q 拉到 0.6901。
2. **`sin_num=16` 的成本也最高**（A/16384 322.8–357.3 ms，比 8 的 189.7–233.8 ms 贵 ~50%）。
3. 所以默认 `8` 是**在给定 Q 定义 + 成本轴下的折中**，不是"每项指标都最好"。
   如果调用方更在意 B（AM-FM 多分量）的捕获率，`sin_num=16` 的 `q_B=0.9955` / `mode2=0.9553`
   比 8 的 0.9740 / 0.9550 更好，代价是纯噪声上的合规行数从 0.33 掉到 0.10。
4. 另外注意 `k` 也随 `sin_num` 变：`sin_num=4` 的 A/4096 还是 **10 阶**（吃满上限），
   8 和 16 都是 **8 阶**（更早达到停止判据）——即 Q 里也混入了"阶数不同"的影响。

### 9.6 默认值变更记录（A/1024 单例 Pareto）

§9.2–§9.5 记录的是 **A/B/C 三例复合 Q** 的扫描，结论是 `sin_smaple_num=8`、`separation_ratio=1.5`。
此后又按 **A/1024 单例**（`Q = 0.5·模式捕获 + 0.5·(1−正交性指数)`）做了一轮 15 方法统一扫描
（`tests/comparison/results/pareto/`），该口径下 `sin_smaple_num=4, separation_ratio=1.2` 明显更优，
**据此把默认值改为 `separation_ratio=1.2`、`sin_smaple_num=4`**：

| 口径 | 默认参数 | Q | 来源 |
|---|---|---|---|
| A/B/C 三例复合（§9.2） | `ratio=1.5, sin_num=8` | 0.7613 | `results/rpsemd_new/pareto_sweep.json` |
| A/1024 单例（现行默认） | `ratio=1.2, sin_num=4` | **0.5891** | `results/pareto/RPSEMD.json` |

新默认在 A/512 上实测 `k=6`、重构 `4.44e-16`、`282 ms`（A/1024 为 `k=10`、`31 ms`）。
两个口径的 Q 不可直接比较（用例与度量都不同），本节只记录"默认值是按哪个口径定的"。

## 10. 架构与参数

### 10.1 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `num_imf` | **`10`** | 目标阶数；`-1` = 不设阶段上限，由停止判据定阶。**本族里唯一一个默认给正整数阶数的类** |
| `separation_ratio` | **`1.2`** | 簇分离阈值：两个簇的中心频率比 `max/min > separation_ratio` 才算"分离"；论文推荐 1.5 |
| `max_clusters` | **`4`** | 最大簇数；`-1` = 不限（试到样本数）/ `None` = 信号长度 / `int ≥ 2`。**注意 `range(2, max_clusters)` 是开区间**，`4` 最多试到 3 簇 |
| `sin_smaple_num` | **`4`** | 每阶辅助正弦的相位数（= 每阶额外的 `EMD(num_imf=1)` 次数）；相位网格 `θ_i = (2π/I)·i`（规范②，§3.4），**不是** `linspace(0, 2π, I)` |
| `res_energy` | `1e-6` | 残差能量门限（相对 `‖S₀‖²`） |
| `standard` | `True` | 聚类时对频率用 z 分数；**返回值换回物理量纲**（§2.2 #5） |
| `cluster_weight` | `0.0` | 选簇的能量权重门限（簇大小 × 平均幅值）；**已评估，默认不启用**（§6） |
| **`cluster_max_samples`** | **`512`** | **聚类前的均匀抽稀上限（兜底）**；`0` = 不抽稀。聚类输入先被极值点降到 N 的 29%–73%（§4.4），该上限只在极值点仍 > 512 时生效（A/4096：1203 → 401 点） |
| `hilbert_mod` | `"FFT"` | 解析信号的 Hilbert 后端，9 种可选（§10.3） |
| `copy` | `True` | 是否复制调用方数组（`False` 时 `decompose` 会在原数组上做 `S -= IMF`） |
| `store_more_info` | `False` | 是否在 `info` 里保留逐阶 `amp` / `freq` / `phases`（体积 = 阶数 × N） |
| `emd_*`（14 个） | — | 原样透传给内层 `EMD`（§10.2） |
| `dtype` | `None` | `None` = 保持输入精度（int / f16 会被提升到 f64）；显式给定时必须是浮点 dtype |
| `safe` | `"unknown"` | 经 `Check.validate_safe` 归一后传给 `Check_Time_and_Signal` |

> **没有 `noise_amp` / `noise_std` / `noise_width`**：辅助的是确定频率的正弦，不是噪声（§1.5 #1）。
>
> **没有 `parallel` / `num_workers`**：与 `EMD` 一致。每阶的 `sin_smaple_num` 次 `EMD` 调用
> 是**纯串行**的，代码里没有任何多进程分支。
>
> **没有顶层 `peaks_backend`**：本类自己的 `find_peaks` 只在停止判据里调一次
> （写死 `mod="both", safe="safe"`），没有后端开关；内层 EMD 用 `emd_peaks_backend`。

|---|---|---|

| `emd_internal_delta` | `0.2` | `internal_delta` |
| `emd_internal_iter` | `50` | `internal_iter` |
| `emd_res_energy` | `1e-6` | `res_energy` |
| `emd_faster` | `True` | `faster` |
| `emd_store_iter_info` | `False` | `store_iter_info` |
| `emd_pre_num_imfs` | `10` | `pre_num_imfs` |

| `emd_safe` | `"safe"` | `safe` |

`sin_smaple_num` 次用于算各相位的 IMF）。

### 10.3 `hilbert_mod`（9 种）

`HILBERT_MODS` 的取值：`scipy` / `Fourth-order Wave` / `FHT` / `SB-Hilbert` /
`Kramers-Kronig` / `FIR` / `HST` / **`FFT`（默认）** / `Optional-order FIR`。
非法值由 `Check.validate_mod(self.hilbert_mod, HILBERT_MODS)` 拒绝。
实测 `FFT` 与 `FHT` 两个后端给出**同一结果**（`k=3`、重构都是 `2.22e-16`，§7）。

### 10.4 `decompose` 流程

```text
输入 S
  ↓ Check_Time_and_Signal(need_T=True)       # 校验 + 拿时间轴 T；非浮点/低精度提升到 f64
  ↓ 重置 self.imfs / self.res = None
  ↓ num_imf != -1 → 预分配 (num_imf, N)，否则用 list
  ↓ original_energy = <S, S>；waves 缓冲 (sin_smaple_num, N)
  ↓ 局部 max_clusters = S.size if self.max_clusters is None else self.max_clusters
  ↓ 阶段循环 n：
  │   imf_result = EMD(S).IMFs
  │   剥不出（shape[0] < 1）→ self.res = S，break        # 无可分分量
  │   IMF = imf_result.squeeze()；z = hilbert(IMF)
  │   amp, freq = get_instantaneous_features(z)
  │   ext = find_peaks(IMF, mod="both")          # 规范①：只在极值点上取样（§3.3）
  │   (freq_c, amp_c) = (freq[ext], amp[ext])；极值点 < 4 → 退回全样本
  │   兜底抽稀：0 < cluster_max_samples < len → freq_c[::ceil(len/max)], amp_c[同理]
  │   center_freq, center_amp, cluster_info =
  │        hierarchical_clustering(freq_c, amp_c, max_clusters, separation_ratio,
  │                              standard, cluster_weight)     # 顺序：频率在前
  │   phases = arange(I) * (2π/I)                # 规范②：不含 2π 重复端点（§3.4）
  │   for i in range(sin_smaple_num)：
  │        waves[i] = center_amp · cos(2π·center_freq·T + phases[i])
  │        内层 EMD(S + waves[i]) → imf_i；剥不出则该相位不计入
  │   row_imf = Σ imf_i / contrib
  │   写 self.imfs[n_imf, :]（或 append）；n_imf += 1；S -= row_imf
  │   显式阶数到点 → self.res = S，break
  │   停止判据：残差单调 / 每向极值 < 2 / <S,S> ≤ res_energy·original_energy → break
  ↓ self.imfs = imfs[:n_imf, :]（显式档）或 asarray(list) / empty((0, N))
  ↓ config_generate() + info + DecompositionResult
```

### 10.5 返回契约

| 字段 | 内容 |
|---|---|
| `IMFs` | `(k, N)`，`dtype` 随输入（§7 实测 f32 全程 float32） |
| `Res` | `(N,)`；**`Res = S − ΣIMFs` 成立**（实测 `recon` 4.44e-16 – 1.33e-15） |
| `info["cluster_infos"]` | 每阶一个 dict：`matrix`（linkage 的 `Z`）、`best_labels`、`target_label` |
| `info["each_center_amp"]` | 每阶辅助正弦的幅值（= 目标簇的平均瞬时幅值） |
| `info["each_center_freq"]` | 每阶辅助正弦的频率（cycles/sample，**物理量纲**） |
| `info["each_phases"]` / `each_amp` / `each_freq` | 仅在 `store_more_info=True` 时有内容，否则 `None` |
| `info["rows"]` | 实际写出的阶数（= `k`） |
| `config` | `RPSEMDConfig`（继承 `Config`，含 `to_dict()`；嵌套 `EMDConfig`） |

> **`info` 里没有 `noise_std`，也没有 `noise_amp`** —— 这是无噪声方法，不是缺字段（§10.6）。

### 10.6 同族一致性（跨 `EMD` / `EEMD` / `CEEMD` / `CEEMDAN` / `ICEEMDAN` / `RPSEMD`）

六个引擎由不同轮次演进而来，以下是**已知的跨类不一致**，调用方需要注意：

| # | 不一致项 | 现状 |
|---|---|---|
| 1 | **噪声参数口径** | `EMD` 无噪声参数；**`EEMD` / `CEEMD` / `CEEMDAN` / `ICEEMDAN` 的 `noise_amp` 都是「幅值系数」**（`σ = noise_amp · std(S)`，无量纲），默认分别是 **0.3 / 0.3 / 0.3 / 0.2**。`ICEEMDAN` 的 `noise_amp` 就是 `β_k` 里的 ε₀：第 1 阶注入幅值同为 `noise_amp · std(S)`，之后按 `std(r_{k−1})` 自适应。旧基线与 PyEMD / PySDKit 用 `noise_width`（**峰峰值**口径 `noise_width · \|max−min\|`），跨库对比前必须换算 |
| 2 | **`num_imf` 是否必填** | `EMD` / `EEMD` / `CEEMDAN` / `ICEEMDAN` 默认 `-1`（自动定阶）；**`CEEMD` 必填**，不传直接 `TypeError` |
| 3 | **`info` 键名** | `EMD`：无噪声键（有 `final_sd`）；`EEMD` / `CEEMD`：`noise_amp`（系数）**+** `noise_std`（绝对标准差）；**`CEEMDAN` / `ICEEMDAN`：只有 `noise_std`，没有 `noise_amp`**。另外 `ICEEMDAN` 的 `info["emd info"]` **恒为空列表** |
| 4 | **注册机制** | 六个类都未 `register_class`；`_Registry.py` 已删除，还有 15 个兄弟模块在引用它（含**旧** `RPSEMD.py`，§11.2） |
| 5 | **并行能力** | 只有 `EEMD` / `CEEMD` / `CEEMDAN` / `ICEEMDAN` 有 `parallel`；`EMD` / `RPSEMD` 无多进程路径，且 **`CEEMDAN` / `ICEEMDAN` 的并行当前无收益**（`spawn` 固定开销摊不平，见 `CEEMDAN_Native_Engine_Report.md` §9.2 与 `ICEEMDAN_Native_Engine_Report.md` §4.3） |
| 6 | **`RPSEMD` 的三处空缺** | **噪声口径：无噪声参数**（辅助的是确定频率的正弦，幅值来自簇的平均瞬时幅值，没有 `noise_amp` / `noise_width`）；**`info` 键名：无 `noise_std`**（只有 `cluster_infos` / `each_center_amp` / `each_center_freq` / `rows`）；**并行能力：无 `parallel` / `num_workers`**，与 `EMD` 一致。另外它默认 `num_imf=10`（本族唯一默认给正整数阶数的类），且**已由 `RPSEMD_NEW.py` 转正为 `RPSEMD.py`**（473 行；旧 149 行实现在提交 `833c1f4`） |

**已经一致的部分**（供核对）：

- **`dtype` 默认值**：六个类都是 `None`（保持输入精度）；`RPSEMD` 的 f32 输入全程 f32
  靠的是 §3 #12（int / 低精度提升到 f64）与 EMD 侧的 `dtype` 透传。
- **残差语义**：六者都满足 `Res = S − ΣIMFs`，重建恒等式成立。
- **内层 EMD 透传**：`EEMD` / `CEEMD` / `CEEMDAN` / `ICEEMDAN` / `RPSEMD` 都用同一套
  `emd_*` 参数，默认值即 EMD 轮的 Pareto 拐点。
- **`peaks_backend`**：`EEMD` / `CEEMD` / `CEEMDAN` / `ICEEMDAN` 有顶层 `peaks_backend`；
  `EMD` 只有 `peaks_backend` 一个（它就是内层）；`RPSEMD` **只有 `emd_peaks_backend`**
  （自己的极值检测写死 `numpy` 语义、无后端开关）。

### 11.2 旧 RPSEMD 基线是怎么造出来的

旧 `RPSEMD.py`（**149 行**、`@register_class("RPSEMD")`）**已随转正被取代**，工作区现在的同名文件
就是 473 行的新引擎。旧实现在当前代码树上有 8 类直接故障：

| # | 位置 | 失败原因 |
|---|---|---|
| 1 | `from .Base import Config, Decomposer, DecompositionResult` | `Config` 已搬到 `.Define`，`Base` 不再导出 → `ImportError` |
| 2 | `from ._Registry import register_class` + `@register_class("RPSEMD")` | `_Registry.py` 已删除 → `ModuleNotFoundError` |
| 3 | `from .Utils import ... is_monotonic` | `Utils` 已无该函数 → 导入期 `ImportError` |
| 4 | `is_monotonic(Res)` 当函数用 | 现为 `monotonic(Res, mod="monotonic", safe="safe")` |
| 5 | `Check_Time_and_Signal(S, T, ...)` 按三元组解包 | 只有 `need_T=True` 才返回三元组，默认二元组 → `ValueError` |
| 6 | 旧 EMD 参数名 `spline_kind` / `max_imf`，且 `EMD.decompose(X, T)` | 现 `EMD` 无 `spline_kind`、用 `num_imf`、`decompose(S)` → `TypeError` |
| 7 | 类体 | 缺 `param_check` / `config_generate` 两个抽象方法 → `TypeError: Can't instantiate abstract class RPSEMD` |
| 8 | `decompose` 内现造 config | 旧实现每次在 `decompose` 里重新构造快照，迁移到新基类要走 `config_generate()` |

**重建方式**：`.scratch/eemd_new/legacy_rpsemd.py` 先读工作区那份源码，判据是里面**还含不含
`_Registry`** —— 工作区现在已是新引擎（不含），所以它会**自动回落到
`git show 833c1f4:src/Modal_Decomposition/RPSEMD.py`** 取回旧源码（运行时会打印
`旧 RPSEMD 来源: 提交 833c1f4`），再按 `PATCHES` 的 **8 条**文本替换打补丁，把补丁后的源码
`exec` 进**动态模块** `Modal_Decomposition.RPSEMD_OLD`，**不往仓库写任何文件**。
产出的旧类参数名是它自己的：`M`、`f`、`max_imf`、`fs`、`spline_kind`、`nbsym`。

**两家不是同一算法**（§8.1），所以 §8 只用它做量级参照：
旧版 `f=None` 时用 **FFT 谱峰**定辅助频率、辅助正弦**单位幅值**、没有聚类参数；
新版用**瞬时频率层次聚类中心** + **簇平均幅值**。旧基线不会因为转正而丢失：
每次运行都由该提交现取现打补丁。
