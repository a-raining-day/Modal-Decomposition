# EMD `faster` 分支四向对比报告（MD-quality / MD-fast / PyEMD / PySDKit）

> 对象: 库内 `src/Modal_Decomposition/EMD.py`
> - **MD-quality** = `EMD(faster=False)` —— **现行库默认**（质量档）: 能量 Cauchy
>   SD 收敛之外还需经典窄带平衡 `|zc−ext|≤1`（过零用 PyEMD 同口径计数）才放行
>   每一行; `sd_thr=0.01` / `max_iter=100` / CubicSpline / nbsym=2（默认可调）。
> - **MD-fast** = `EMD(faster=True)` —— 旧高速档（`faster` 引入前的库默认）:
>   SD 收敛即停。
> 对照: **PyEMD**（EMD-signal 1.9.0, cubic/nbsym=2 默认）与 **PySDKit**
> （`ref/pysdkit` vendored, 默认档）——两者在既有验证中逐位一致。
> 复现: `python tests/comparison/bench_emd_faster.py` → 原始数据
> `tests/comparison/results/emd_faster_raw.json`（含逐行迭代数组）。
> 信号: `tests/comparison/signals.py` —— case A 双音调 37/113 Hz + 白噪 0.1;
> case B AM-FM + 89 Hz + 二次趋势（无噪）; case C 纯白噪声。
> 指标: t=中位耗时; k=行数; valid=满足 |zc−ext|≤1 的行数（对四实现的结果行
> 统一重算, 无平台信号下与 PyEMD 内部判据一致）; corr_*=任一 IMF 与真值分量最大
> |corr|; share1=纯噪声首 IMF 能量占比; iters=MD 每行筛分迭代数。

## 0. 结论速览

1. **质量档达到设计目标**: 在带噪/长信号场景, MD-quality 的**行级 valid 与弱
   音调捕获全面追近 PyEMD/PySDKit** —— A/65536: corr37 0.9759（= PyEMD）、
   valid 11/12（Py 13/14）、弱音调 c113 0.82（F 档仅 0.62; Py 0.92）;
   C/16384 纯噪声 valid 11/11（= Py 12/12 的档位）。
2. **干净信号零代价（实测）**: case B 全网格 MD-quality 与 MD-fast **逐位相同**
   （同 k、同 corr、同迭代数、同耗时）——窄带门在已窄带的行上立即满足。
3. **速度**: 默认档相对 PyEMD 在 case A 快 2.1–5.6×、case B 快 1.2–2.3×、
   case C 快 1.1–4.2×（A/16384 因 max_iter 边界略低 2.0×）。相对旧默认
   （MD-fast）在噪声场景慢 1.6–6.8×（这是质量换速度的显式开关成本）, 干净
   信号无差。
4. **诚实边界**: ① 默认 `max_iter=100` 是质量档行级保证的有效上限 ——
   A/16384、A/65536 各有一行在迭代预算内未达窄带而被接受（valid 10/11、
   11/12）; 需要 PyEMD 同级行级保证时建议 `max_iter` 提至 300+（成本线性）;
   ② 弱音调 113 Hz 单行捕获仍比 PyEMD 低 0.05–0.10（A/4096 0.71 vs 0.76、
   A/65536 0.82 vs 0.92）——差距从 F 档的 0.14–0.30 收窄到一半以下, 残留
   差距属停止判据工程差异（PyEMD 的 svar 幅值归一判据更严, 见
   `docs/EMD_Quality_Gap_and_Optimization.md`）; ③ A/1024 短样本上质量档
   corr37 0.865 略低于 F 档 0.884（混沌性行分配差异, valid 仍更优 7/7 vs 6/7）。

## 1. 分支语义与默认变更

`faster` 形参（bool, 默认 **False**）选择停止策略, 与 `sd_thr` / `max_iter` /
`spline_kind` 等正交:

| 分支 | 停止条件 | 行级 | 相对成本 |
|---|---|---|---|
| MD-fast (`faster=True`) | `sd = Σm²/Σh² < sd_thr` | 不保证 \|zc−ext\|≤1 | 基准（旧默认语义） |
| MD-quality (`faster=False`, 默认) | 上式 **且** 当前 h 满足 `\|zc−ext\|≤1` | 每行强制窄带（受 max_iter 上限约束） | 带噪/长信号迭代上升; 干净信号 ≈0 |

行为变更提示: `EMD()` 不带参现在等价于旧文档中的 "质量档/窄带门变体 V4"
（`docs/EMD_Quality_Gap_and_Optimization.md`）, 而非旧默认; 旧默认语义由
`EMD(faster=True)` 保留。库内 `ICEEMDAN`/`RPSEMD`/`CEEMD` 内部调用原生 EMD
的路径自动随默认升级为质量档。

窄带门口径（评审采纳）: `|zc−ext|≤1` 中 zc 对齐 PyEMD `indzer` 计数（严格
符号积 + 零点段中点）、ext 对齐 MD 原生 `Utils.Peaks` 规则（`S[i-1]<S[i]>=S[i+1]`,
平台取升沿右缘）。无平台信号（本报告 A/B/C）上两引擎计数等价; 平台/量化信号上
与 PyEMD simple 的平台规则（中点 + 先升后降）不同——行为差异与依据见
`docs/EMD_vs_PyEMD_Detailed_Comparison.md` 实验 E-H。

速度口径: 全部数字为同进程/同脚本中位计时（`bench_emd_faster.py`）, 不混用
跨日绝对耗时; 外部实现 65536 跑 2 次、其余 3 次, MD 3 次。

## 6. 用法建议与速度-质量结论

- **默认即质量档**: `EMD()` / `Function.EMD` / 内部 ensemble（ICEEMDAN/RPSEMD/
  CEEMD）自动获得行级窄带保证。对行级纯度无要求、只求吞吐的批量场景显式
  传 `faster=True`。
- **质量档的成本形态**: 噪声/长信号迭代预算上升 1.6–6.8×（A/65536: 56→314
  次总迭代, 126→794 ms）, 换来的收益是 corr37 +0.02–0.10、弱音调 c113
  +0.10–0.20、valid 从 ~60% 到 ~100%。干净信号（case B 类）成本为 0。
- **若要 PyEMD 级行级保证的最严格场景**（A/16384+ 或 C/16384+, 剩 1 行由
  `max_iter=100` 上限导致）: 提高 `max_iter`（300–800）或收紧 `sd_thr`
  （0.002–0.0005）——上轮变体实验（V7/V8, `docs/EMD_Quality_Gap_and_Optimization.md`）
  显示 sd=0.002 + 窄带门在 65536 可达 valid 13/14（= PyEMD）且仍快 1.9×。
- **对 PyEMD/PySDKit 的总体位置**: 质量档在全部噪声网格上单行捕获与行级
  valid 达 PyEMD 档位, 弱音调仍有 0.05–0.10 单行差距（行分配粒度差异, 非
  泄漏——主验证 corr(Res,tone)<0.0002; 两行组合可找回 0.92+）; 速度除
  16384 噪声同量级外保持 1.4–5.6× 优势。
