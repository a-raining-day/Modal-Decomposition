# Hilbert 后端实测与优化报告（`Utils.Hilbert`）

- 日期：2026-10-19**（含本轮优化：新增 `"FFT"` 后端 + `"FHT"` 自适应 + 零拷贝内核）**
- 目标：`src/Modal_Decomposition/Utils/Hilbert.py`（薄封装）→ `Utils/_Hilbert/__init__.py`（分发）
  → `_fft.py`（新增，默认后端）/ `_fht.py`（自适应）/ `_scipy_backend.py`；C 内核 `_fht_native`
- 基准脚本：`tests/comparison/bench_hilbert.py`（单进程、warm-up 后 best/median）
- 原始数据：`tests/comparison/results/utils/hilbert/Hilbert_Backend_Results.json`
- 用例：`tests/utils/test_Hilbert_deep.py`（**72 passed + 1 strict xfail**）
- **结论一句话**：
  1. **`hilbert(S, "FHT")` 现在在所有尺寸上都比 scipy 快**（0.48–0.89×，任意长度），
     靠的不是把 SAO 内核写得更快，而是**自适应分发**：2 的幂且 n ≤ 512 走 SAO 内核，
     其余走新增的实半谱法（rfft + irfft）。副产品：**非 2 的幂长度的零填充伪影消失了**
     （以前相对 L2 误差 0.5%–6%，现在 ≤4e-15）。
  2. **`hilbert(S, "FFT")`（新默认）** 为纯实半谱实现：0.59–0.99× scipy，任意长度精确；
     最紧的是 n=4096（10 轮交替测量的中位数比 0.84×），其余尺寸 0.59–0.73×。
  3. **SAO 内核本身**（`hilbert_transform` / `fht_forward` 原语）在 n ≥ 4096 上仍比 scipy
     慢 1.1–1.7×（n ≤ 1024 反而更快，0.40–0.82×），且仍保留"零填充到 2 的幂"的语义与伪影；
     本轮只把包装层做了零拷贝优化（**5%–27%**）。

## 2. 方法（口径）

- **计时**：同进程内 `reps` 次独立调用取 **best（min）**，括号内为 median；每条记录先 warm-up。
  `reps = clip(2e7/n, 3, 50)`。跨进程/跨日绝对值有 10%–20% 波动，**同表内比值可靠**。
- **内存**：`tracemalloc` 峰值增量（已验证能看见 NumPy 缓冲区：`np.zeros(8 MB)` 计到 8.0 MB）。
- **准确性**：参考恒为 `scipy.signal.hilbert`。记录 `max|z−z_ref|`、相对 L2、包络最大相对误差，
  非 2 的幂另按边缘/中段分开（填充伪影的分布特征）。
- **效果**：单音（解析解 `exp(jθ)`）、调幅（已知包络）、两音+噪声（无解析真值，只比与 scipy 的差异）；
  幅度纹波/相位误差/瞬时频率误差剔除两端各 5%（解析信号端点效应 scipy 同样有）。

## 7. 为什么 SAO 内核打不过 scipy（以及本轮挤出了多少）

SAO 的 `hilbert()` 其实是 **两次复数 FFT**（`fft_dif` + `ifft_dit`，位反转域里直接置零负频率），
不是 Hartley 变换 —— 也就是说它和 scipy 算法相同，只是实现是**标量 C**。
每元素工作量（`_fht_native.pyx:77`）：

1. `np.zeros(2n)`（旧版）→ 2. `z[0:2n:2] = signal`（跨步写）→ 3. C `hilbert()` → 4. `z[1::2] *= -1` →
5. 新建 complex 数组并从 `z[0::2]`/`z[1::2]` 两次跨步拷贝（旧版）。

第 2、5 步共 3 次跨步内存搬运；pocketfft 的 SIMD + 无跨步布局把差距拉开到 1.5–2×。
本轮**能改的都改了**（不改 C 语义）：

| 改动 | 文件 | 效果 |
|---|---|---|
| 零拷贝：直接分配 `complex128` 输出，以其 `float64` 视图作为 SAO 的 2n-double 交错缓冲**原地**调用；删掉旧版"2n 临时缓冲 + 两次跨步拼复数" | `_fht_native.pyx`（本项目包装层；**SAO C 源码未改**） | **+5%–27%**（见下表） |
| 自适应分发：n 为 2 的幂且 ≤512 → SAO 内核；其余 → 实半谱法 | `_fht.py` | 大尺寸从 1.5–2.0× 降到 **0.45–0.88×**；非 2 的幂伪影消失 |
| 新增 `"FFT"` 后端（rfft/irfft 实半谱，2 次实变换 ≈ 1 次复 FFT） | `_fft.py`（新增） | 0.59–0.99×，任意长度精确 |
| 实半谱的 rfft/irfft 优先用 `scipy.fft`（装了 scipy 时；同一 pocketfft 内核、包装层更瘦），缺失时回退 `np.fft` | `_fft.py` | 比 `np.fft` 快 **5%–18%**（n=4096: 17.6→13.8 µs；n=16384: 63→54 µs），把 n=4096 从"持平"推到"小胜 0.84×" |

零拷贝前后的 `hilbert(S,"FHT")`（当时仍是纯 SAO 内核，µs，best）：

| n | scipy | 优化后内核 | 优化前内核 | 提速 |
|---|---|---|---|---|
| 256 | 10.3 | 5.2 | 6.6 | 1.27× |
| 1 024 | 18.7 | 17.2 | 18.0 | 1.05× |
| 4 096 | 41.7 | 65.2 | 76.4 | 1.17× |
| 16 384 | 171.8 | 338.1 | 380.2 | 1.12× |
| 65 536 | 1 876.9 | 1 841.5 | 2 002.1 | 1.09× |
| 262 144 | 15 823 | 10 806 | 11 384 | 1.05× |
| 1 048 576 | 50 480 | 53 820 | 60 459 | 1.12× |
| 4 194 304 | 264 182 | 256 906 | 301 360 | 1.17× |

**为什么不再继续优化 C 内核**：要让 2 次标量复 FFT 全面快过 pocketfft，需要 SIMD 化整个
radix-2 递归 + 消除位反转域跨步访问，收益上限也只是"追平"；而"改成两次*实*变换"能把
工作量减半 —— 这正是 `"FFT"`/自适应路径做的事，且不改动第三方代码。所以本轮选择
**换算法**而不是**改 C**。

`tests/utils/test_Hilbert_deep.py`（**72 passed + 1 strict xfail**）：

- 分发契约：三个后端 + 枚举成员 + 未知/未实现模式 + 默认值（`"FFT"`）；

- FHT 原语：DHT 定义对照、自逆、填充长度、位反转；
- 边界：2-D / 复数 / float32 / int / list / 空 / 长度 1–3 / NaN；
- Cache：scipy 后端惰性注册 `scipy.signal`；
- 性能烟测：n=256 与 16384 打出三后端耗时与相对 scipy 的比值。

`test_documented_capital_spelling_accepted` 仍是 **strict xfail**（缺陷 #1）。

**建议**

1. 默认 `"FFT"`：任意长度、0.59–0.99× scipy（n=4096 最紧，约 0.84×）、无需编译内核。
2. 想要最快：`"FHT"`（自适应）0.48–0.89×，n ≤ 512 的 2 的幂走 C 内核；
   非 2 的幂自动回落实半谱，**不会**再有零填充问题。
3. 只有在需要"原汁原味 SAO 语义"（指定位反转/零填充）时才直接调用
   `fht_forward` / `fht_inverse` / `hilbert_transform`。
4. 修 #1（大小写）与 #3（scipy kwargs）成本极低，是 LMD/Envelope 走 Hilbert 路径的前置条件。

---

## 10. 局限

- 单机单次测量；best-of-N 抑制噪声，但个别点（尤其 n=4096/65536）会在 10%–20% 内跳动，
  **比值**比绝对值可靠。
- `tracemalloc` 只统计 Python/NumPy 分配器；FHT 内核缓冲走 `np.zeros` 故被计入。
- 最大测到 4 194 304 点。
- **未做 LMD/Envelope 端到端**：两个消费方当前各自不可用（§8 末）。
- 自适应阈值 512 是在本机（32 逻辑核、pocketfft SIMD）测出的交叉点；不同 CPU 上
  阈值可能落在 256–1024 之间，属可调常量 `_fht._SMALL_NATIVE_MAX`。
